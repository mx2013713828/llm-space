# 代码质量与评审约定 (Code Review Guidelines)

本指南设定了项目的架构设计底线，用于引导 Agent 进行自动代码审查。

## 1. SOLID 架构设计原则
*   **单一职责 (SRP)**：一个类/一个函数只做一件事情。如果函数代码超过 80 行，必须考虑逻辑拆分。
*   **开闭原则 (OCP)**：对扩展开放，对修改关闭。优先使用配置驱动和策略模式。
*   **接口隔离 (ISP)**：不应强迫客户端依赖它们不使用的方法。

## 2. 局部代码坏味道 (Code Smell)
审查代码时，以下情况将被判定为“坏味道”，应当立即重构：
*   **魔法值 (Magic Numbers)**：禁止在核心计算或条件判断中硬编码无解释的数字或字符串，必须提取为常数（`const CONST_NAME = ...`）。
*   **深层嵌套 (Deep Nesting)**：`if-else` 或循环嵌套层数超过 3 层。应使用 guard clauses（卫语句）提前 return 退出以平铺结构。
*   **未捕获的异步 Promise**：所有的异步请求与 await 调用必须使用 `try-catch` 包裹，防止 Node.js 进程崩溃。

## 3. 安全防线 (Security Defense)
*   **输入校验**：对于外界或用户传入的路径，必须使用 `path.resolve` 校验其是否越界脱离工作空间，严防路径穿越漏洞（Path Traversal）。
*   **敏感信息**：密钥、Token、数据库连接串禁止硬编码入源码，必须在 `.env` 中加载并在运行时从 `process.env` 读取。
